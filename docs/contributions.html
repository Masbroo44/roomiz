Travail d'équipe

  • Répartition claire dès le départ : on a listé les écrans de l'app ensemble, puis chacun a choisi sa partie. Chaque personne garde un dossier dans pages/ et un fichier dans api/, pour pouvoir avancer en même temps sans se marcher dessus.
  • Décisions prises en groupe : avant de coder, on s'est mis d'accord ensemble sur une charte UI commune (couleurs, polices, rayons, vocabulaire de l'app comme "Toquer" ou "Vibe Check") pour que toutes les pages se ressemblent même en travaillant chacun de son côté.
  • Organisation Git discutée ensemble : une branche par personne créée depuis develop, des petits commits clairs en français, et une Pull Request relue par un autre membre avant d'intégrer le code dans develop.
  • Un seul responsable des composants partagés : pour éviter les conflits et garder une app cohérente, seul Samuel modifie components/. Les autres lui demandent avant de changer quelque chose là-dedans, au lieu de le faire chacun dans son coin.
  • Communication régulière : on s'est tenus au courant de l'avancée de chacun pour éviter les blocages, par exemple si quelqu'un a besoin d'un composant qui n'existe pas encore.
  • Entraide sur le code : chacun relit ce que les autres ont déjà fait avant de commencer sa propre partie, pour garder le même style de code partout dans le projet.
